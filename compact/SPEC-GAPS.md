# compact suite: spec gaps (contract tester). F33 gaps are in F33-SPEC-GAPS.md.

## F41 (statements 79-86)

1. Text length: F41.2 says the final text is "still <= 560 chars", but the F35.3 text it extends is already about 600 chars (path-dependent) and the final adds 22. Tested as <= 662 (the F35.3 bound of 640 plus 22). The spec should state <= 662 (stale form <= 802) or restate the bound.
2. Statement 84 "lost arm": a black box cannot set the cached t directly. The tests make the measure-time arm fail by rejecting `$.fs.exists` during `session.measure` (the arm text needs it), then restore it. A pre-F41 plugin ALSO delivers here (it treats the failure as "file absent" and arms anyway), so C84 does not fail on the old code. Probes with `fs.stat`, `fs.read`, `fs.write`, `session.usage` and `session.id` rejecting did not lose the arm in the old plugin either. The spec should name a seam (for example an exported `armFor(t)` or a test-only throw point) so C84 can force the lost-arm case.
3. Statement 84 text at delivery time: F33.3 builds the text at arm time because `$.fs.exists` is allowed there; F41.3 arms inside `tool.call` where no `$` call is allowed. Which verb (`write` or `update`) the safety-net text carries is therefore unspecified. C84 asserts only the header, `352k of 400k` and the absence of `imminent`.
4. Statement 79 `/coach` line: `handoff nudge: next at 325k` after the first delivery is asserted (F33.5 line, F41.1 "F33.5 text follows"). It is not stated in F41.6 itself.
5. Rounding of pct for the 365k text (91.25): floor, same reading as F33 gap 1 (`91%`).
6. Statement 81 says "k=2 text"; k is not observable from the entry, so only the `365k of 400k` header, `91%` and ` Compaction is imminent.` are checked.
7. `nudge_finalPercent` below the range (10) is asserted to clamp to 50 (F = 200,000). The spec gives the range 50..99 and only tests 120 explicitly.
8. `nudge_finalPercent=75` with `nudge_atPercent` 75 (final at 300k, equal to T(0)): tested as one entry by the coincidence rule.
9. Debug log content: `k` on `arm` is asserted 0 for the 300k arm; `lastK` and `t` on `deliver`/`reset` are not asserted. `final` is asserted false on a regular deliver and true on arm/deliver of a final-only event. `ev: "skip"` reasons `agent_subagent` and `no_window` are taken literally from the spec's "e.g." list; `below_half` is not tested (ambiguous with the `reset` reason of the same name).
10. Debug log I/O: the spec says "append" and "renamed". The kit has no rename or append op in the harness. The test double treats `$.fs.write` as replace unless the event carries `append`, and `process.run` `mv a b` as a rename. Rotation is asserted by outcome only: `nudge-debug.1.jsonl` holds the old 1,000,001-byte content and the main file holds exactly one line after the first event (the arm). A plugin that rotates through another verb cannot be observed; add that verb to the harness once it is known.
11. "Disabled = no file touched": tested as no `$.fs` call of any op on a `nudge-debug*` path, for `nudge_debugLog=false` and for `mod_nudge_enabled=false`.
12. "Logged once to the plugin log" is not asserted (the existing meta write also logs; the lines are indistinguishable). Only no-throw and continued nudging are asserted.
13. Statement 86 amendments: C27 (both tests) and C37 (`next` after the first delivery is 325,000). F33/F35 tests that deliver at 350k after 300k, or at 400k (C53), still hold by the highest-k rule; at t >= 360k those nudges also carry ` Compaction is imminent.`, which no old assertion checks.
14. Existing C33/C34/C62 assert "no write to the handoffs dir". The F41 debug log lives in that dir and is on by default, so the harness `handoffDirWrites` now excludes `nudge-debug*` paths (C34 "no write before the first delivery" would otherwise contradict the `arm` line F41.4 logs at 300k). The spec should state that the debug log is exempt from the F33.4 file contract.

## F43 (statements 87-93)

1. Harness additions (not spec gaps, listed for the implementer): `Cfg.autoCompact` puts `autoCompactThreshold` into the `breakdown` returned by `session.usage({breakdown})` (and makes a breakdown present, overhead 20,000 if unset); `S.usageTokens` is what `session.usage()` reports as `context.tokens` (default: the last measured t); `S.usageCalls` logs every usage call with its clock time and whether it asked for a breakdown.
2. F43.2 does not say which arguments the live read passes. The tests count ALL `session.usage` calls made during main-loop `tool.call`s (reset after the measure has settled), so a live read that also asks for a breakdown is fine, but a second call per tool.call would fail C90.
3. Throttle start (C90): "at most once per 10 s per session" does not say whether the first call may happen right after session start. The tests idle 11 s after start before the first tool.call so either reading passes; the "fourth after 10 s" call is made 10,001 ms after the third (exactly 10,000 ms is not tested).
4. Throttle and failure (C90): the tests assume a failed usage() still counts as an attempt only through the 10 s rule; the test that clears the failure waits 11 s before expecting the live read. Whether a failure re-opens the throttle early is unspecified and untested.
5. Statement 89 "the final is armed per rules (one nudge counts as both)": asserted as one entry reporting the live t (`356k of 400k`) that carries ` Compaction is imminent.` The k of that entry is not observable (same as F41 gap 6). Whether the pending k=1 arm from the cached 349,116 measure is replaced by the live arm (assumed: yes, header 356k) is an inference from F41.3 "highest k, reports the current t".
6. Percent of the 355k final: 88.75% asserted as floor `88%` (same reading as F33 gap 1 / F41 gap 5).
7. Statement 87 with `autoCompactThreshold` other than 367k (380k, 460k) is not in F43.6; the tests derive it from F43.1 (`T(k) < C - 12k`, `F = min(ceil(W*pct/100), C - 12k)`): 380k -> final 360k, no 375k; 460k -> regulars 375k, 400k, 425k still fire and the final stays 360k. Non-integer, 0 and negative thresholds are asserted to fall back to W-33k ("integer > 0" in F43.1).
8. Statement 88 "no autoCompactThreshold available" is tested three ways: breakdown without the field, no breakdown at all, and usage() rejecting is NOT tested for the refresh (F33.2 already swallows it).
9. Statement 92 length: the 120-char path is produced by giving `session.id` a long value (the plugin builds the path from it; the test asserts the path found in the text is exactly 120 chars as a precondition). If the plugin takes the id from somewhere else the precondition fails rather than the length check.
10. Statement 92 "right after the headings list": asserted as ` <sentence>` immediately following `## Exact next step.` (the final heading of the F35.3 list). F43.3 does not say whether other heading lists (F36/F42 forms) exist; if the template gains headings the anchor in C92 and in `template()` (35-handoff-quality) must follow.
11. Amended length bounds: F43.3 gives 760 for "the full text" (120-char path). The old bounds were 640 (normal) and 662 (final); both are amended to 760. The STALE form (old 780) is not covered by F43.3; it is amended to 970 (780 + the 190-char sentence) as a derived bound. The spec should state the stale bound.
12. Statement 93: the `skip` line is asserted to be written on subagent `tool.call`s (the old tests only produced skips through subagent `session.measure`). F43.4 says "once per distinct reason per cycle"; the existing C85 tests (measure path, once) are unchanged and still apply; the cycle reset used is `session.compact` (manual).
13. Statement 86's amendment text ("jump 290k->410k ... highest k=4; then nothing until 425k") is superseded by F43.1: the jump now delivers one entry (the final, 102%, imminent) and nothing at 425k either. The spec should restate statement 86 / 27.
14. F41 C84 and F33 C38 "no $ call besides clock.after/clock.now" are amended to also allow `session.usage` on main-loop calls (F43.2); the subagent form of C38 stays strict.

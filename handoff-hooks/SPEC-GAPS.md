# Spec gaps (ACs / behaviours not covered)

- 75 s Haiku timeout (`timeout after 75s`): cannot be shortened; a test would cost 75 s. Not covered.
- 3.3 degraded file: cannot be provoked from outside. Not covered.
- Unwritable handoffs dir (section 7): not tested (permission semantics fragile as root/macOS); only exit-0 behaviour on garbage stdin covered.
- Excerpt details (last 40 messages, 2500/30000 char caps, `[tool Name: ...]` rendering) are specified in section 4 but no AC pins them; only `USER: <msg>` on stdin (AC 13) is checked.
- Several per-message truncation limits (600/150/200/1500 chars, 4000 Haiku) only partly asserted (AC 12, 15, 24).
- AC 24 "stale-agent file + large sections" with exact trim boundaries: the test asserts a prefix-drop invariant and cap, not exact byte thresholds.
- Haiku-heading position when a failure line exists with fallback enabled and a fresh meta: covered implicitly only.

## F37 (AC 72-80)

- AC 73 k=8: the eight non-user sections are each size-capped (decision lines ~220 chars, 10 max), so their drop cannot be forced from transcript content alone within 20,000 chars. Test inflates the header with a very long nonexistent `cwd`, which removes the `## Git` section; it therefore asserts the first 7 PRESENT names of F37.2 are dropped (all non-user sections) and Last user messages (8 entries) is kept. A literal "first 8 names incl. Git" is untestable black-box. k=1 and k=3 are literal (bisection over task count).
- AC 73 calibration is by bisection on a fixture knob (task count / cwd length); the spec gives no section sizes.
- AC 75: "N = chars not inlined" tested as len(file.strip()) - len(inlined text), i.e. the blank-line separator before the first cut section is counted as not inlined. "(sections: <names>)" tested as heading text without `## `, joined ", ", for every section not inlined. "Greedy" cut (next whole section would not have fit under 9,700) is tested only with a 400-char tolerance because the spec does not say whether the continuation line counts toward 9,700.
- AC 75 (F37.5 amendment, long names): shortened section-name list `, ...` form is not asserted exactly; only total < 10,000 per part and the continuation regex.
- AC 77: position of `inline_cut` among health keys is unspecified; tests require the 13 F36 keys in their order plus `inline_cut` anywhere (AC 49 tests updated accordingly).
- AC 77 `inline_cut` prediction is tested at 12,000 (true) and ~5,000 (false) only; the exact 10,000 boundary and the degraded-warning prefix contribution are not tested.
- AC 78 as written (19,000 chars, two parts) is borderline infeasible with whole-section cuts (two budgets of ~9,430 + ~9,650). Superseded by F37.6: tests deliver 17,500/19,000/20,000-char files and sections up to ~5,500 chars across parts 1-3 and compare line-for-line ignoring blank lines (a section split across parts at a line boundary is allowed for oversized sections).
- Part-3 continuation line (path-only form) and part-2 continuation (`part 3 below and in`) are tested by regex; the exact N semantics for parts 2-3 are not asserted.
- AC 80: the template is located relative to HANDOFF_HOOKS_DIR (`<hooks dir>/../settings.template.json`); command matching is regex `postcompact-inject.py --part[ =]K`. Bootstrap/canary registration (F37.6) is covered only by the canary test's settings assertion (three 10 s hooks plus the 90 s PreCompact).
- AC 75 section names in the continuation line: accepted either as the full heading text or with a trailing parenthetical (e.g. "(last 30)") removed; the spec does not say which.

## F38 (AC 81-92)

- AC 81 is read as a fresh agent file = 400-byte body with mtime 1 min old and no meta. Stale agent in AC 89 = mtime 40 min, no meta (no `stale_sections`, so status `reduced` per F38.6; with meta `stale_sections` F36.D still gives `degraded` and existing F36 tests keep asserting that).
- AC 82: argv is compared as an exact list (excluding `claude` itself), recorded NUL-separated by the shim so the two `""` elements are checked. The cwd of the child ("fresh temp dir") is not asserted; only that the session cwd gains no files.
- AC 83: invalid-model cases tested: `bad model;`, `a b`, `x/y`, `m;rm`, `$(x)`, empty and a non-ASCII char; one valid exotic value `claude-sonnet-4.5_x`.
- AC 84: only the literal `0` of either switch disables; `1`, empty, `00`, `false` enable (F38.1 "exactly `0`").
- AC 85 truncation: "truncated to 4,000 chars" is asserted as a run of 3,997..4,000 chars (the `...` marker form of `trunc` is not pinned for excerpt text). The `[tool Name: <key>]` line is asserted as its own line after the message text when the assistant message also has text; for a tool-only assistant message the test accepts the line with or without an `ASSISTANT: ` prefix (spec does not say). 300-char key-input cut asserted as 297..300 chars. The "last message alone exceeds 120,000" branch cannot be reached because messages are cut to 4,000 chars first; not tested.
- AC 85 large transcript: "stdin length <= 120,000" plus > 115,000 (whole messages dropped only as needed) and a first line of `USER: ` / `ASSISTANT: ` followed by a message that starts at its beginning.
- AC 86: threshold tested at 49 vs 50 stripped chars. The "exception class name" reason is not provokable from outside and is not tested.
- AC 87: the shim does `exec sleep N` (new `sleepx` knob in helpers.py) so killing the shim PID also ends the sleeper; a shim that forks `sleep` would hold the pipe open and make any implementation using `subprocess.run(timeout=...)` wait for it. `HANDOFF_SUMMARY_TIMEOUT` validity (0, 301, non-numeric -> 75 s) is not tested: the 75 s default is too slow to observe; only `2` and `1` are exercised.
- AC 88: "cut to 6,000 chars, ending `...`" is asserted as exactly 5,997 body chars + `...` (total 6,000), matching the F35 `trunc` convention; exactly 6,000 and 5,000 chars are kept whole.
- AC 90: the agent body is capped at 5,000 chars (section 4) so it cannot be the calibration knob, and the header/lead/footer plus agent plus 8 x 600-char user messages plus a 6,000-char summary cannot reach 20,000 chars without a long header. Knob = length of a nonexistent `cwd` (header only, never trimmed), swept in steps of 100 with a 10-step refinement for the narrow "summary gone, Last user messages kept" window. A nonexistent cwd removes `## Git`, so "the eight non-user facts sections" are the seven that exist; the tests assert all seven are dropped before the summary is shortened, that the summary is then cut to 200..5,999 chars ending `...`, that it disappears (silently, no failure line) before `## Last user messages (oldest first)` is dropped, and that while the summary is whole the dropped facts form a prefix of the F37.2 order. The "fewer than 200 chars remain" boundary itself is not pinned to an exact byte.
- AC 91: the "where the summary would be" position under `HANDOFF_TEST_FAULT=fallback` is asserted as after the agent section and before `## Facts (auto-extracted)`; with an absent agent, before Facts as the first section after the header.
- AC 92: health field order is asserted only as `fallback` immediately followed by `summary_model`; the full key order is amended in test_f36.py to `... fallback, summary_model, duration_ms ...`.
- F38.6 `status` for a stale agent WITH `stale_sections` and summary ok stays `degraded` (F36.D "unchanged in meaning"; existing F36 test kept). The literal F38.6 sentence ("otherwise reduced when the summary is ok") conflicts; the F36 reading was kept.
- Not tested (outside ACs 81-92): `HOOK_VERSION` minor bump, the canary setting `HANDOFF_SUMMARY_MODEL=haiku` (test_f36_canary.py asserts the canary's own `--model haiku` / `--setting-sources project` argv for its main sessions, which F38 does not supersede), the inject `HANDOFF DEGRADED: ... Haiku fallback failed.` wording (F38.7: inject unchanged).
